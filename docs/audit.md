# Audit docházky k 17. listopadu 2026

Audit zahrnul registraci stanice, sběr a příjem událostí, podání a rozhodnutí žádosti, nahrání propustky po návratu, schválení měsíce, export, webové účty a distribuci. Testy používaly dočasné účty, databázová schémata a kontejnery.

## Co audit ověřuje

- HTTP scénář běží proti PHP a dočasnému PostgreSQL. Ověřuje oddělení rolí a týmů, duplicitní události, chybějící propustku, odmítnutí předčasného nahrání, schválení a přepočet mzdy. Test WebAuthn prochází registrací, přihlášením a odebráním klíče ve virtuálním autentizátoru Chromia. [WebAuthn](../web/tests/authenticator.mjs)
- Devět scénářů UI s řízenými odpověďmi API ověřilo i chybové stavy. Další scénář v Chromiu nad Nginx, PHP-FPM a PostgreSQL prošel rolemi zaměstnance, vedoucího a účtárny. Ověřil narovnání a uložení propustky, práci rozdělenou návštěvou lékaře, stažení odpovídajícího CSV a vykreslení dokumentace Stoplight. [Test nasazení](../tests/deploy.sh)
- Hlavní stránka používá předkompilované šablony Vue a politiku CSP, která dovoluje skripty pouze ze stejného původu. OpenCV zpracuje fotografii v samostatném webovém workeru, jehož politika blokuje síťové požadavky přes fetch a WebSocket. Prohlížeč odešle fotografii až po potvrzení uložení.
- Windows x64 balíček se sestavil. Self-test nad .NET a SQLite na Linuxu ověřil klasifikaci interaktivních relací, opakování přenosu a uvolnění záznamu z fronty po potvrzení centrály. [Windows agent](../agent/Program.cs)
- PCOV v kontrolním běhu naměřil **830 z 900 spustitelných řádků PHP (92,2 %)** v `src/`, včetně tříd, které sada vůbec nepoužije. Absence dosáhly 98,2 %, výpočet docházky 95,6 %, mzdy 98,5 %, identita 88,0 % a zařízení 81,0 %. Čitatel je sjednocením jednotkových testů, HTTP požadavků a konzolových příkazů. Samostatný test v doméně Samba běží mimo měření. Pro TypeScript a C# audit sleduje konkrétní scénáře. [Měření pokrytí](../tests/coverage.sh)
- Po obnovení zálohy PostgreSQL 17 do oddělené databáze test ověřil shodu kontrolních součtů verzí mzdového CSV i propustky včetně vazby na zaměstnance a žádost. Frekvenci záloh, jejich dobu uchování a oddělené úložiště nastaví provozovatel. [Postup zálohy a obnovy](../deploy/backup.md)

## Otevřené body před plošným nasazením

1. Na stanici Windows připojené do vaší domény proveďte pilot s vlastní GPO a Traefikem. Ověřte spuštění pod LocalSystem, skutečné Security a Kernel-Power události, spánek, odpojení sítě a aktualizaci agenta. Testovací doména ověřila protokol registrace. Windows služba sleduje místní interaktivní a cached-interactive přihlášení. Důvod odchodu ze stanice se dá prozatím doplnit webovou žádostí.
2. Zkontrolujte fotoaparát na používaných telefonech a čitelnost narovnané fotografie skutečné propustky. Automatická kontrola prohlížeče doplňuje ruční ověření se čtečkou obrazovky a reprezentativními uživateli.
3. V době auditu registry nehlásily známé zranitelnosti v uzamčených balíčcích Composeru, NuGetu ani produkčních npm závislostech. Plný npm audit hlásil upozornění vysoké závažnosti v `picomatch`, který používají nástroje pro sestavení. V projektu zpracovává vzory ze zdrojové konfigurace. Autorita k datu auditu neuváděla vydanou opravenou verzi. Po jejím vydání aktualizujte lockfile a ověřte sestavení. [Bezpečnostní oznámení](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)
4. Zápisy centrály se při společných operacích řadí pomocí databázového zámku. Konzistentní čtení výkazů a přehledu uzávěrky může běžet souběžně se zápisy. Pro odhad kapacity větší instalace zbývá měření se skutečným počtem stanic při ranním přihlášení. Audit nezahrnoval zátěžový test.
